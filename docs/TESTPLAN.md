# Test Plan for the Current COBOL Accounting Application

This test plan is intended for validating the current business logic and implementation of the COBOL-based school accounting system before moving the same behavior into a Node.js application.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
|---|---|---|---|---|---|---|---|
| TC-001 | Application starts and displays the main menu | COBOL application compiled successfully and executable is available | 1. Run the compiled application. 2. Observe the initial screen. | The application displays the menu options: View Balance, Credit Account, Debit Account, and Exit. | Not executed yet | Not Run | Baseline startup validation. |
| TC-002 | User views the current balance | Application is running and initial balance is available | 1. Select option 1 from the menu. | The application displays the current balance, for example 001000.00, and returns to the menu. | Not executed yet | Not Run | Confirms the read path from the data program. |
| TC-003 | User credits funds to the account | Application is running and the current balance is known | 1. Select option 2 from the menu. 2. Enter a valid credit amount such as 250.00. 3. Review the result. | The application displays the credited amount and the updated balance. The new balance reflects the addition of the credit amount. | Not executed yet | Not Run | Covers the positive update path. |
| TC-004 | User debits funds from the account when sufficient funds exist | Application is running and the account has enough balance | 1. Select option 3 from the menu. 2. Enter a debit amount that is less than or equal to the current balance, such as 100.00. 3. Review the result. | The application subtracts the debit amount from the balance and displays the updated balance. | Not executed yet | Not Run | Covers the successful debit path. |
| TC-005 | User attempts a debit greater than the available balance | Application is running and the current balance is lower than the attempted debit amount | 1. Select option 3 from the menu. 2. Enter a debit amount larger than the current balance, such as 5000.00. | The application displays an insufficient funds message and does not change the balance. | Not executed yet | Not Run | Confirms the business rule for insufficient funds. |
| TC-006 | User enters an invalid menu option | Application is running | 1. Select a value outside the valid menu options, such as 9. | The application displays an invalid choice message and returns to the menu. | Not executed yet | Not Run | Validates error handling for invalid input. |
| TC-007 | User exits the application | Application is running | 1. Select option 4 from the menu. | The application exits gracefully and displays a goodbye message. | Not executed yet | Not Run | Confirms the termination path. |
| TC-008 | Balance is preserved across multiple operations in the same session | Application is running and a prior transaction has occurred | 1. Perform a credit or debit operation. 2. Select option 1 to view the updated balance. 3. Perform another transaction. | The balance shown after each operation reflects the previous transaction and remains consistent across operations. | Not executed yet | Not Run | Validates state persistence within the current process. |
| TC-009 | User performs a full happy-path flow | Application is running with the initial balance | 1. View the balance. 2. Credit a known amount. 3. View the balance again. 4. Debit a smaller amount. 5. View the balance again. | The balance changes correctly after each transaction and the final balance matches the expected arithmetic result. | Not executed yet | Not Run | End-to-end business flow validation. |
| TC-010 | User enters a transaction amount and the application processes the input | Application is running and a credit/debit operation is selected | 1. Select option 2 or 3. 2. Enter a numeric amount. 3. Observe the response. | The application accepts the numeric input and uses it in the transaction logic. | Not executed yet | Not Run | Verifies input handling for transaction amounts. |
